# MCP в NeuroMita

NeuroMita умеет подключаться к серверам **Model Context Protocol (MCP)** и
использовать их инструменты для расширения возможностей LLM-персонажей. Из
коробки поддерживаются два транспорта:

- **stdio** — локальные серверы, запускаемые как подпроцесс (например, через
  `npx`, `uvx` или `python -m`);
- **streamable HTTP** — удалённые серверы по `http(s)://`.

## Как это работает

1. NeuroMita выступает **MCP-клиентом**: она читает список инструментов
   включённых серверов.
2. Эти инструменты прозрачно добавляются в общий набор инструментов LLM
   (через `ToolManager`) и попадают в нативные tool calls модели.
3. Когда модель запрашивает такой инструмент, NeuroMita делегирует вызов
   серверу и возвращает результат модели.

Для каждого включённого сервера держится одно **живое соединение** (пул):
оно переиспользуется между вызовами и автоматически переподключается при
обрыве.

## Включение

MCP-серверы задаются в `settings.json` ключом `MCP_SERVERS` — список объектов:

```json
{
  "MCP_SERVERS": [
    {
      "server_id": "filesystem",
      "name": "Filesystem",
      "transport": "stdio",
      "enabled": true,
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem"],
      "env": {},
      "timeout": 60
    },
    {
      "server_id": "weather",
      "name": "Weather API",
      "transport": "http",
      "enabled": true,
      "url": "https://mcp.example.com/weather",
      "headers": {
        "Authorization": "Bearer <token>"
      },
      "timeout": 60
    }
  ]
}
```

### Поля

| Поле | Тип | Описание |
| --- | --- | --- |
| `server_id` | строка | Уникальный идентификатор сервера (обязательно) |
| `name` | строка | Человекочитаемое имя |
| `transport` | строка | `stdio` или `http` (синоним `streamable_http`) |
| `enabled` | bool | Включён ли сервер |
| `command` | строка | Команда для stdio (например, `npx`) |
| `args` | массив | Аргументы команды |
| `env` | объект | Дополнительные переменные окружения |
| `url` | строка | Конечная точка streamable HTTP |
| `headers` | объект | HTTP-заголовки (например, API-ключ) |
| `timeout` | число | Таймаут вызова инструмента, секунды |

## Совместимость с native tool calls

Инструменты MCP работают через нативный механизм tool calls (режим
`TOOLS_MODE=native`) и доступны тем же моделям, что и встроенные инструменты
(`calculator`, `web_search` и т.д.). Инструменты MCP появляются в списке
инструментов даже тогда, когда все локальные инструменты выключены.

## Требования

- Python-пакет **`mcp`** (official SDK) должен быть установлен. Он добавлен в
  `requirements.txt`. Если пакет отсутствует, MCP-серверы просто не активируются,
  остальная часть приложения работает как раньше.
- Используется SDK **`mcp` версии 2.x** (`mcp>=2`). Серверы в этом проекте
  написаны под `MCPServer` (v2), клиент адаптирован под v2 (в т.ч. транспорта
  HTTP — `streamable_http_client`).

## Настройка через интерфейс

В **Настройки → MCP** есть раздел для управления серверами: добавление,
редактирование и удаление серверов (stdio/HTTP), включение/выключение, а также
кнопка «Обновить инструменты». Секция скрыта по умолчанию — включите её в
**Настройки → Общие → Видимые разделы**, если она не видна.

## Встроенный сервер

С релизом поставляется встроенный MCP-сервер `mcp_system_interaction_server.py`
(взаимодействие с Windows: запуск приложений, блокнот, обои, файлы на рабочем
столе, блокировка экрана, фальшивый BSOD). Он автоматически копируется в корень
сборки и **авто-регистрируется**: при первом запуске, если его нет в
`MCP_SERVERS`, приложение само добавляет его с путём относительно папки игры
(работает при любом пути установки). Чтобы отключить — выключите сервер в
разделе MCP или удалите запись.

## Ограничения текущей версии

- Список инструментов кэшируется после первого успешного подключения и
  обновляется по требованию (кнопка «Обновить инструменты»).
